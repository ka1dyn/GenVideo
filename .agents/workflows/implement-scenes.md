# /implement-scenes {project_id} {section}

특정 섹션의 Remotion 영상 씬(Scene)을 컴포넌트 주석에 직접 기획하고, 이를 바탕으로 실제 코드를 순차적으로 구현하는 워크플로우입니다.

## 0. 사전 조건 검사

작업을 시작하기 전, 다음 파일들이 존재하는지 확인하세요. 만약 하나라도 누락된 파일이나 경로가 있다면 즉시 실행을 중단하고 사용자에게 문제를 알립니다.

- `public/{project_id}/{section}/` 폴더
- `src/constants/theme.ts` 파일 <-- 읽기 전용입니다.
- `src/projects/{project_id}/{section}/sequences.tsx` 파일

## Phase 1: 사전 준비 및 기획 (1회성)

본격적인 씬 구현에 앞서 아래 단계들을 단 1회 수행하여, 프로젝트의 전체 맥락과 디자인 규칙을 완벽히 숙지하세요.

1. **Remotion 지식 리마인드 (필독)**
   - 파일 열기 도구(`view_file`)를 사용해 **`.agents/skills/remotion-best-practices/SKILL.md`** 파일을 반드시 1회 미리 읽습니다. (매 Chunk 단계마다 반복해서 읽을 필요는 없습니다.)
2. **대본 및 기획서 파악**
   - 아래 두 파일을 꼼꼼히 읽고, 해당 섹션의 전반적인 분위기와 대본의 맥락을 완벽히 파악하세요.
   - `public/{project_id}/{section}/{section}.txt` (해당 섹션 원본 대본)
   - `public/{project_id}/{section}/{section}_plan.md` (해당 섹션 애니메이션 기획서 개요)
3. **디자인 페르소나**
   - **역할**: "뼈대는 Vercel처럼 정교하게, 질감은 펜 스케치처럼 따뜻하게." 최고 수준의 구조적 깔끔함과 미니멀리즘을 추구하면서도 친근함을 잃지 않는 수석 모션 디자이너이자 Remotion 개발자입니다.
   - **미니멀리즘과 구조적 레이아웃(정교한 뼈대와 배치)**: 뻔한 중앙 정렬이나 예술적인 기교보다는 타이포그래피, 넉넉한 여백, 정교한 Grid/Flexbox 정렬을 사용하여 세련된 정보 배치를 1순위로 두세요. 텍스트는 핵심 단어나 짧은 문구만 사용하세요.
   - **스케치 느낌의 질감(친근함, 따뜻함)**: 펜으로 그린듯한 드로잉 그림 위주로 그리며, Wobble과 같은 효과로 손그림 느낌을 살리세요.
   - **기획 우선순위**: 복잡한 그림보다 텍스트(타이포그래피), 여백, 점, 선, 도형을 활용한 구조적 배치를 우선적으로 고려합니다. 포인트나 강조가 필요할 때 드로잉 그림을 절제하여 사용합니다.
   - **절대 금지**: `✅`, `💡` 등 시스템 이모지 삽입 절대 금지. 가위, 전구 등 유치한 아이콘 금지.
   - **색상 원칙**: 차갑고 딱딱한 분위기를 막기 위해 따뜻한 라이트 모드 색상 위주로 전개. 임의 하드코딩 금지 (`theme.ts` 상수 필수).
   - **폰트 크기 원칙**: `theme.ts`의 폰트 사이즈는 **1920×1080 영상 해상도** 기준입니다. 웹 기준(16px 등)과 비교하지 마세요. `SIZE_MD`가 48px인 것은 영상에서 적절한 본문 크기이며, 임의로 축소하지 마세요.
   - **한국어 원칙**: 고유명사, 약어를 제외한 모든 단어를 한국어로 작성하세요.

## Phase 2: 씬 단위 반복 작업 (Chunking Iteration)

맥락 파악이 끝났다면, `src/projects/{project_id}/{section}/sequences.tsx` 파일을 엽니다. 이 파일 내의 Scene을 **최대 2개씩 묶어서(Chunk 단위)** 순차적으로 작업합니다.
각 Chunk(예: Scene 1, 2)를 작업할 때마다 다음 Step을 순차적으로 반복 수행하세요.

> [!CAUTION]
> **Batch Processing 금지 및 물리적 순서 엄수**
>
> 1. 절대로 전체 섹션을 한꺼번에 기획하거나 구현하지 마세요. 반드시 **최대 2개 씬** 단위로만 끊어서 진행해야 합니다.
> 2. 현재 Chunk의 작업(Step 1~3)이 완전히 종료되기 전까지, **절대로 다음 Chunk의 씬들을 미리 기획(JSDoc 작성 등)하거나 예측하지 마세요.** 다음 씬들은 철저히 보류(Leave as is) 상태로 두어야 합니다.

### Step 1: 기획 구체화

1. `sequences.tsx` 내 현재 대상 Scene 상단의 JSDoc 주석(`/** [Scene X] ... */`) 마커를 아래 **필수 항목을 모두 포함**한 기획으로 교체하세요. 각 `@` 항목에 구체적인 내용을 한 줄 이상 서술해야 하며, 빈 값이나 "추후 결정" 등의 모호한 기술은 금지합니다.

   ```
   /** [Scene X]
    * @narrative — 이 씬이 전달할 핵심 메시지 또는 시청자 인상 (1줄)
    * @layout — 주요 요소 배치 구조 (Grid/Flex, 정렬, 여백 전략)
    * @elements — 렌더링할 요소 목록 (텍스트·SVG·도형 등, 각각 한 줄씩)
    * @animation — 등장(in) / 유지(sustain) / 퇴장(out) 모션 계획
    * @tokens — 사용할 theme.ts 디자인 토큰 (COLORS.xx, FONTS.xx 등)
    */
   ```

2. `implementation_plan.md` 파일은 오직 **현재 진행 중인 Chunk(최대 2개 씬)의 기획(연출 및 컴포넌트)만 작성하여 완전히 덮어쓰기(Overwrite)** 하세요. 이전 기획 내용이 계속 누적되어 현재 씬 구현에 혼동을 주는 것을 방지하기 위함입니다. 과거 씬의 작업 내역은 이미 코드로 남아있으므로 계획서에 유지할 필요가 없습니다.
3. **(필수)** JSDoc 마커 교체와 실제 코드 구현을 한 번의 툴 호출(Tool call)로 묶어서 시도하면 파싱 에러율이 매우 높습니다. **따라서 반드시 JSDoc 마커를 수정하는 첫 번째 파일 편집을 단독으로 실행하여 확정한 뒤, 사용자 대기(승인) 없이 자율적으로 이어서 두 번째 파일 편집을 실행해 실제 코드를 구현(Step 2)하세요.**

### Step 2: 직접 구현

직전 Step에서 기획한 레이아웃과 동작을 바탕으로 `sequences.tsx`의 씬 컴포넌트 내부 및 필요한 부속(SVG, UI) 컴포넌트들의 코드를 작성합니다.

> [!WARNING]
> **파일 활동 범위 제한 (병렬 실행 안전)**
>
> 다른 섹션과의 충돌을 방지하기 위해, **파일 생성·수정·삭제가 허용되는 경로**는 아래 두 곳뿐입니다. 이 외의 경로에 있는 파일은 **읽기만 허용**됩니다.
>
> - `src/projects/{project_id}/{section}/` — 담당 섹션 폴더 (sequences.tsx 등)
> - `src/projects/{project_id}/components/` — 공유 컴포넌트 폴더 (svg/, ui/)
>
> 프로젝트 루트, 다른 섹션 폴더, `scripts/`, `src/constants/`, `src/shared-components/` 등에 파일을 생성하거나 수정하지 마세요.

- 필요한 SVG 파일을 `src/projects/{project_id}/components/svg/`에 `.tsx` 확장자로 작성하세요. **(주의: SVG 파일 내부에는 `<text>` 태그 등 글자를 직접 그리는 로직을 절대 포함하지 마세요. 모든 텍스트는 반드시 부모 씬 컴포넌트에서 기본 HTML 태그(`div`, `span` 등)와 `theme.ts`의 폰트 토큰을 사용하여 SVG 외부에 렌더링해야 합니다. SVG 컴포넌트는 순수 복잡한 그림이나 드로잉 아이콘 용도로만 제한하세요.)**
- 만약 앞으로도 정말 많이 사용할, 광범위한 용도의 컴포넌트가 있다면(카드 레이아웃 등) 매우 신중하게 분리하여 `src/projects/{project_id}/components/ui/`에 구현하세요. 해당 씬에서만 사용한다면 내부적으로 구현하세요.
- **모든 props는 반드시 기본값**을 지정하여 아무 props를 지정하지 않아도 렌더링 크래시가 발생하지 않도록 방어 코드를 작성하세요.

### Step 3: 필수 검토 (task.md 작성)

코딩을 마친 직후 다음 순서 씬으로 넘어가기 전, 오직 현재 Chunk에 대한 QA(품질보증) 목적으로만 `task.md` 하단에 아래 템플릿 양식을 복사해 이어서 작성(Append)하세요.

- 단순 `[x]` 표기는 금지됩니다. 반드시 코드를 돌아본 후 괄호 안에 결과 한 줄 요약을 서술하세요.

```markdown
### Chunk [N] 검토 (Scene X~Y)

- [ ] 물리적 통제: 자막 하단 150px / 화면 밖으로 나간 요소 없음 (요약: )
- [ ] z-index 레이어 순서: (요약: )
- [ ] 색상, 폰트, 폰트사이즈(fontSize)를 하드코딩이 아닌 theme.ts에 명시된 디자인 토큰으로 작성 (요약: )
- [ ] 한국어 단어, 문장 사용: (요약: )
```

## Phase 3: 최종 검토 및 완료 보고 (Final Review)

task.md파일을 읽고 모든 Chunk에 대한 필수 QA 검토가 작성되었는지 마지막으로 확인합니다. 누락된 부분이 있다면 해당 부분을 다시 검토하세요. (자막, 하드코딩, z-index, 한국어 등)
해당 `{section}`의 모든 Scene 작업이 완료되었다면 다음 명령어를 수행해 문법 수정을 진행합니다.

// turbo

```bash
export PATH=$PATH:/opt/homebrew/bin && npm run lint
```

다른 프로젝트에서 발생한 에러는 수정하지 않습니다. 현재 프로젝트 내의 에러만 수정하세요.

// turbo

```bash
python3 scripts/update-gallery.py {project_id}
```

최종적으로 사용자에게 작업 결과를 요약 보고하고, 영상 결과물을 갤러리에서 검토해 달라고 요청하세요.
